# 薯餅桌寵使用說明

## 安裝與啟動

薯餅桌寵是 Windows 10/11 的 .NET 8 WPF 自包含單檔可攜版，不必另外安裝 .NET。解壓或複製 `dist/ShuBingDesktopPet-win-x64` 資料夾後，執行 `ShuBingDesktopPet.exe`；最終發佈的 EXE 已內含所需執行環境與角色資產。開發版則直接由 Visual Studio 或 `dotnet run` 啟動。

程式會在透明、無邊框、永遠置頂且不出現在工作列的視窗中顯示薯餅。關閉程式請使用系統匣或桌寵右鍵選單的「退出」。

## 基本操作

- 在薯餅上按住左鍵，移動超過 6 DIP 後即可拖曳；拖曳期間會暫停漫遊，放開後保存位置與螢幕。
- 單擊會抬爪，雙擊會開心跳躍。
- 游標在頭部區域左右來回移動會觸發摸頭；靜止時薯餅會依游標方向追視，靠近中心時會呼吸、眨眼或整理毛髮。
- 在薯餅本體按右鍵會開啟與系統匣相同的選單。
- 右鍵寵物或系統匣選「餵食薯餅」，再選「種子棒（薯餅實拍）」。薯餅會播放本人啃種子棒的實拍連續動作，完成後顯示「吃飽了！」並播放 HappyJump。
- 餵食期間會暫停漫遊、拖曳及其他左鍵互動；完成後恢復原本狀態。每次完成後有 3 秒冷卻，冷卻中選擇食物不會重複計數。
- 若開啟滑鼠穿透，桌寵不會接收滑鼠操作；請從系統匣關閉「滑鼠穿透」後再拖曳或互動。

## 設定

從系統匣「設定」開啟設定視窗：

- 「啟用漫遊」：開啟後會在工作區內隨機走動與停留；關閉後停在目前位置，但仍可拖曳及互動。
- 「漫遊範圍」：選擇「目前螢幕」或「所有螢幕」。所有螢幕模式會穿越虛擬桌面中的螢幕入口，並避開工作列。
- 「速度」：慢、正常、快。
- 「大小」：75%–150%，以等比例縮放完整視窗，不是裁切圖片。
- 「滑鼠穿透」：預設關閉；開啟後由系統匣恢復操作。
- 「啟用 OBS 擷取視窗」：開啟後會啟用獨立透明 `薯餅 OBS 擷取` 來源視窗，可直接供 OBS Window Capture 使用。
- 「OBS 擷取解析度」：固定 1280x720、1920x1080、2560x1440、3840x2160，變更後會即時重排並保存，重啟後套用。
- 「開機啟動」：預設關閉；啟用後會在目前使用者的 Windows 啟動資料夾建立捷徑。

系統匣選單另有「顯示／隱藏」、「漫遊」、「OBS 擷取」、「滑鼠穿透」、「設定」、「回到主螢幕」及「退出」。

## OBS 取景步驟

一般桌寵是讓整個 192×208 小視窗在 Windows 桌面上移動；OBS 的視窗來源只取得視窗內部，不會把 Windows 桌面座標帶進場景，所以直接擷取一般桌寵時只會看到原地走路。OBS 模式會另開固定 16:9 透明畫布，讓薯餅在畫布內改變位置。

1. 開啟「啟用 OBS 擷取視窗」，並選擇與場景相同或接近的解析度。
2. 在 OBS 新增「視窗擷取」，視窗選擇「薯餅 OBS 擷取」。擷取方法先用「自動」；若畫面不正常，改用 Windows 10/11 方法並保留用戶端區域。
3. 關閉擷取游標；若目前擷取一般薯餅所用的透明度／alpha 設定已正常，直接沿用同一組設定。
4. 把來源配合場景縮放。主桌寵不會被自動隱藏，需要時可用系統匣既有的「隱藏」只留下 OBS 來源。

OBS 擷取視窗永遠滑鼠穿透、不置頂且不顯示在工作列；請從系統匣或設定視窗控制它。
「啟用漫遊」與慢／正常／快三段速度會同時套用到一般桌寵及 OBS 擷取視窗。

滑鼠穿透開啟時仍可從系統匣進入「餵食薯餅」；餵食期間的 overlay 不接收滑鼠事件。

## 設定與資料位置

設定會保存於：`%LOCALAPPDATA%\ShuBingDesktopPet\settings.json`。內容包含漫遊狀態、範圍、速度、大小、滑鼠穿透、OBS 擷取、開機啟動、最後位置與螢幕識別，以及 `TotalFeedCount`、`LastFedUtc`、`LastFoodType` 餵食統計。

設定 schema 6 可向後讀取舊設定，新增欄位會採用安全的預設值。螢幕拔除、解析度或 DPI 改變後，程式會將寵物夾回可見工作區。

若要重設設定，先退出程式，再備份後刪除 `settings.json`，下次啟動會使用預設值（漫遊開啟、目前螢幕、正常速度、100%、OBS 擷取關閉／1920×1080、穿透關閉、開機啟動關閉）。

## 疑難排解

### 找不到系統匣圖示

確認程式仍在執行；若圖示被 Windows 隱藏，請到工作列的隱藏圖示區查看。重新啟動最新版 EXE 可重新建立圖示。

### 無法拖曳

先從系統匣關閉滑鼠穿透。所有螢幕模式下，拖曳到另一螢幕後放開即可；程式會依游標所在工作區修正邊界。

### OBS 裡只會原地跑

確認來源選到「薯餅 OBS 擷取」，不是一般的小型桌寵視窗。若來源是黑底或透明度不正確，先將擷取方法切換為 Windows 10/11，再檢查目前可用於一般桌寵的透明度／alpha 設定；筆電多 GPU 環境也要確認 OBS 與程式使用相容的 GPU。

### 薯餅卡在邊界或位置失效

從系統匣選「回到主螢幕」。若顯示器剛拔除或 DPI 剛變更，等待畫面設定事件完成後再操作。

### 設定沒有保存

確認程式有權限寫入 `%LOCALAPPDATA%`，並確定按下「儲存」而不是「取消」。損壞的 JSON 會被安全地退回預設值。

### 開機啟動失效

確認設定中的「開機啟動」已開啟，且可攜版資料夾未被移動；啟動捷徑指向最後一次執行的 EXE。Windows 安全性軟體或公司政策可能阻擋啟動資料夾捷徑。

## Twitch Bits 餵食

1. 到 [Twitch Developer Console](https://dev.twitch.tv/console) 建立 Application，將 Client Type 設為 Public，複製 Client ID。若 Console 要求 OAuth Redirect URL，可填 `http://localhost`；Device Code 流程不會使用這個回呼網址。
2. 在薯餅設定視窗啟用 Twitch，貼上 Client ID，設定最低 Bits，儲存後從系統匣選「連線／重新授權 Twitch」。
3. 應用程式會開啟 Device Code 頁面；用頻道擁有者帳號完成授權。授權範圍只有 `bits:read`，收到頻道 Cheer 便會排入 Pellet 餵食佇列（最多 20 次）。

連線使用 Twitch EventSub WebSocket 的 `channel.cheer`。Token 儲存在設定資料夾的 `twitch-auth.json`，Access/Refresh token 以 Windows CurrentUser DPAPI 加密；Client ID、頻道名稱與到期資料也僅供連線恢復使用。中斷/重新授權會清除這份檔案。這個功能不依賴 Streamlabs、綠界或其他外部打賞服務。
